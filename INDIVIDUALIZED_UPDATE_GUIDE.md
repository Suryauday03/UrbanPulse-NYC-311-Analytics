# Urban Pulse - Individualized Update Guide

This update adds project-specific functionality without changing the previously validated 100,000-row extraction, cleaning, or MySQL loading logic.

## What is different in this edition

1. **Distinct dashboard presentation** - a light teal civic-operations theme and revised application description.
2. **Data Quality & Sampling dashboard page** - adds a dedicated view of ID integrity, date-order anomalies, coordinate completeness, missing-field rates, status/closure-date mismatches, and monthly sample coverage against the extraction's source-count report.
3. **Five additional SQL investigations (16-20)** - status/closure reconciliation, field completeness, top complaint types by borough, weekday-hour hot spots, and resolution-duration bands.
4. **Automated database audit** - `src/project_audit.py` writes timestamped JSON and Markdown checks for main/staging record counts, unique IDs, chronology, coordinates and duration metrics.
5. **Unit tests** - `tests/test_data_quality_rules.py` covers duplicate flags, resolution-duration rules, and coordinate validation.

These are substantive additions for analysis and reproducibility, not cosmetic renaming. Keep the project title and dataset identity required by the GUVI brief. Do not claim the new dashboard page has been tested until you run it locally.

## Apply the update safely on Windows

1. Close the running Streamlit terminal with `Ctrl+C`.
2. Make a backup of your current project folder. For example, copy `C:\Users\surya\UrbanPulse` to `C:\Users\surya\UrbanPulse_backup_before_update`.
3. Extract this update ZIP into `C:\Users\surya\UrbanPulse` and allow it to replace **only** `dashboard\app.py` when Windows asks. The other files are new additions.
4. Do not replace or delete `.env`, `data`, or the existing extraction/cleaning/loading scripts.
5. Confirm that this source-count report is present in `reports`:
   `nyc311_monthly_source_counts_20261115_113852.csv`
   (or the matching monthly source-count report generated by your final extraction run).

## Run the new checks

Open Command Prompt:

```cmd
cd C:\Users\surya\UrbanPulse
.venv\Scripts\activate
python -m unittest discover -s tests -v
python src\project_audit.py
```

The unit tests should report 3 tests passed. The database audit should report that the main table contains 100,000 rows, 100,000 unique IDs, no missing IDs, no duplicate flags, and that staging and main row counts match.

## Launch the updated dashboard

```cmd
streamlit run dashboard\app.py
```

A new **Data Quality & Sampling** page should appear in the sidebar. Open it with the full date range (2020-01-01 to 2026-11-14) and no borough or complaint filters to see the full monthly sample-to-source comparison. If the monthly source-count report is missing, the page explains which file to copy into `reports`.

The app uses a light teal theme from `.streamlit/config.toml`. Stop and restart Streamlit after adding this theme file.

## Run the extra SQL investigations

Open `sql\additional_investigations_16_20.sql` in MySQL Workbench and execute each numbered query individually. These queries extend (they do not replace) the original 15 GUVI investigations.
